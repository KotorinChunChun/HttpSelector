# HttpSelector

チャット、メール、その他のアプリから開いたHTTP/HTTPSリンクを、意図したブラウザー・プロファイルへ渡すためのWindows用ツールです。URLのルールで自動振り分けするか、その場で利用者が選択できます。

## 解決する課題

WindowsでChromeやEdgeを使う際、外部アプリから開いたリンクが、最後にアクティブだったプロファイルなど、意図しないプロファイルで開かれることがあります。仕事用・個人用・別組織用のプロファイルを使い分けている場合、適切なプロファイルでリンクを開き直す手間が生じます。

HttpSelectorは、リンクを最初から狙ったプロファイルで開けるようにし、次の問題を防ぐことを目的としています。

- **誤ったプロファイルでのログイン・認証**：OAuth認証フローなどで一度しか使えないワンタイムURLを扱う際、意図しないプロファイルで先に開いてしまうことを避けます。使い切ったURLを後から正しいプロファイルで開き直しても、同じ操作をやり直せない場合に重要です。
- **プロファイルを開き直す手間**：リンクをコピーして別のプロファイルを起動し、貼り直すといった作業を減らします。
- **意図しない情報共有やリクエスト送信**：誤ったプロファイルのログイン状態で操作することで、意図しない相手・組織への情報共有や、不適切なリクエスト送信につながるリスクを減らします。

主目的は、ログイン後のアカウント切り替えではなく、**リンクを開く入口で適切なプロファイルを選ぶこと**です。アカウントの認証やアクセス権をアプリが代行・保証するものではありません。高リスクURLの警告は、この役割を補助する機能です。

## 利用前に知っておいてほしいこと

**導入直後はルールが少ないため確認が頻繁に表示され、リンクを開くたびに操作がおよそ2クリック増えます。** プロファイルを選び、確認フォームで「開く」を押す流れです。実際の回数はダブルクリックなどの操作設定や、ルール登録の有無によって変わります。

よく使うリンクの条件を登録していくと、自動振り分けによって確認の回数を減らせます。ただし、安全性の警告やShiftによる意図的な選び直しは省略しません。初期の確認操作を許容してでも、ワンタイムURLや重要なリンクの開き先を管理したい方に向いています。

## 主な機能

- HTTP/HTTPSリンクをルールで自動振り分け、または手動でプロファイルを選択
- Edge、Chrome、Firefoxの既存プロファイルを自動検出
- お気に入り、エイリアス、コメント、並び順
- ダブルクリック・キーボード操作とURLの既定ルール
- URLのドメイン・パス・クエリを個別選択し、自動起動または関連付けの質問省略を設定
- 全角英字・類似文字・大手サービス名の誤字や偽ドメインを開く前に警告
- Quad9へのドメイン照会と、確認できない場合の警告
- KotorinToysからの無表示起動・状態取得・画面表示・正常停止
- URLパターンを既定で保存しない設計
- SQLite設定のHMAC-SHA256完全性チェックと、検証用の鍵のDPAPI保護

## 署名付きMSIXで配布する理由

本ツールは、WindowsのHTTP/HTTPSプロトコルの関連付けに介在し、チャット・メール・その他のアプリからブラウザーへ渡されるリンクの受付先になります。認証用URLなども扱う入口であるため、発行元と配布物の改ざんの有無を確認できることを重視しています。

このセキュリティ上の方針と関連付け登録のため、**通常利用は署名付きMSIXからのインストールを必須**としています。署名はリンク先の安全性を保証するものではありません。初回は証明書の発行元と拇印を確認してから導入してください。正式版はMicrosoft Storeへの掲載を予定していますが、現在は署名付きベータ版を配布しています。

[MSIX導入手順](docs/INSTALL_MSIX.md) ／ [GitHub Release](https://github.com/KotorinChunChun/HttpSelector/releases/latest) ／ [公開サイト](https://excel-chunchun.sakura.ne.jp/download/HttpSelector.html)

## プライバシーとセキュリティ

URLのパラメーターには、認証コード・一時トークン・個人情報などの機密情報が含まれる可能性があります。そのため、**保存する情報は振り分けに必要な最小限となるようにしています。** URL全体や変動するパラメーターを安易に固定せず、ドメインや安定したパスなど、目的を満たす最小限の条件を選んでください。

新しい連携フォームでは既定はドメインのみ固定し、パス・クエリはOFFです。ONにした部分の文字列と生成済み正規表現だけを保存します。`tenantId`等をONにすると、その名前と値も端末内DBへ保存されます。「保存」は設定だけを保存して折りたたみを閉じます。URLを開くには続けて「開く」を押してください。

URLパターンの自動記録は既定でOFFです。有効にした場合も、自動記録では末尾・パラメータ値・フラグメントを `*` に置き換えます。既定ルールの新規登録初期値と「ワイルドカード」でも、URLの認証情報・末尾パス要素・クエリ値・フラグメントを `*` に置き換えます。保存前に一致範囲と残る情報を確認してください。既存ルールや手動入力はそのまま保存され、DB自体は暗号化していません。

開く直前に端末内のパターン判定とQuad9へのDNS over HTTPS照会を行います。Quad9へ送るのはサブドメインを含むASCIIホスト名で、元URL、認証情報、ポート、パス、クエリ、フラグメントは送りません。警告を表示する前に照会が行われる場合があります。Quad9は接続元IPなどの通信情報を認識できるため、匿名通信ではありません。ローカル名、IPリテラル、公開suffixを確認できない名前は外部照会の対象外です。WindowsのDNS設定は変更しません。

危険性が疑われる場合と照会できない場合は、キャンセルを初期選択にした確認画面を表示します。ルール一致や割り込みオフでも適用し、明示的に「それでも開く」を選ぶまで、ブラウザ起動・ドメイン連携・履歴記録を行いません。「ブロックなし」は安全保証ではなく、短縮URLの展開、対象ページの取得、リダイレクト追跡は行いません。検査用の永続URLログは追加していません。詳しくは[プライバシーポリシー案](docs/PRIVACY_POLICY.md)を参照してください。

ブラウザには受け取った元URLを起動引数として渡します。ブラウザ実行ファイルパスは設定DBへ保存せず、Windowsレジストリと既知のインストール先から都度解決します。
