## 実装方針

### 技術構成

- 言語: Rust
- UI: Win32 APIによるネイティブデスクトップUI
- DB: SQLite
- 完全性保護: HMAC-SHA256
- 鍵保護: Windows DPAPI CurrentUser
- 配布: Inno Setup（ユーザー単位インストール）

### モジュール

```text
src/
├── main.rs          エントリーポイント、単一起動
├── app.rs           アプリケーション制御
├── browser.rs       ブラウザ解決・安全な起動
├── profile_scan.rs  Edge/Chrome/Firefox検出
├── model.rs         ドメインモデル
├── storage.rs       SQLite永続化
├── integrity.rs     DPAPI・HMAC・バックアップ
├── url_input.rs     URL検証・表示変換
└── ui/              Win32画面、タイル、設定画面
```

### セキュリティ上の判断

- URLをシェルコマンド文字列へ連結しない。
- ブラウザは `std::process::Command` の引数としてURLとプロファイル識別子を渡す。
- DBに実行ファイルパスを保存しない。
- HMAC鍵は別ファイルへDPAPI暗号化して保存する。
- SQLiteを閉じた状態でDBファイルを署名し、署名は別ファイルに保存する。
- 正常保存前のDBと署名をバックアップし、改変・破損時の復旧候補にする。
- URL履歴設定がOFFの間、URLをファイル・DB・診断ログへ書き出さない。

### 完全性保護の限界

DPAPI CurrentUserとHMACは、設定ファイルの偶発的破損や単純な改変の検出を目的とする。同じWindowsユーザー権限で実行される悪意あるプログラムに対する完全な防御は保証しない。

## Microsoft Store対応計画（2026-08-31）

依頼された「Microsoft Store 公開方針.md」に従い、正式配布をMSIX + Storeへ移す。自己署名証明書は開発用として扱い、約2か月後に決まる署名方針とPartner CenterのIdentityを差し替え可能にする。Store提出自体には開発者による有料証明書の購入は不要。

- フェーズ1: MSIXのPackage Familyに基づいて保存先、Mutex、ウィンドウクラスを分離。開発用と正式版、非MSIX版の混線を防ぐ。既存データは自動移動しない。
- フェーズ2: `packaging/release-config.json` とガード付きPowerShell 7スクリプトを追加。Plan/Build/Verifyを分け、betaのみ永続的な開発証明書を使う。stableはPartner Centerの正式Identityを必須にして未署名MSIXを生成する。
- フェーズ3: beta MSIXを生成してManifest、署名、構成、個人情報混入を検証。ローカル導入とStore移行の手順・残課題を記録する。
- 各フェーズで必要なテストとビルドを実行してコミットする。既存の未コミット文書・削除・`gomi.md` は含めない。
- `runFullTrust` はブラウザー設定の読み取りとブラウザー起動のために必要。管理者権限、サービス、ドライバー、独自アップデーターは使わない。HTTP/HTTPSの候補はMSIX Manifestで宣言し、既定アプリの選択は利用者がWindows設定で行う。審査で機能説明が必要になるため、受理を保証しない。
- Storeが更新を管理するため、App Installer・Web/FTP配布・独自更新チェックは作らない。既存Inno Setupは従来方式として残す。
- この作業では証明書の信頼登録・インストール・Storeへの提出は実行しない。公開前に別ユーザーまたはクリーンVMで導入・URL関連付け・更新・削除の実機検証を行う。
