# HttpSelector v0.0.1 実装計画・報告

## 実装方針

### 技術構成

- 言語: Rust
- UI: Win32 APIによるネイティブデスクトップUI
- DB: SQLite
- 完全性保護: HMAC-SHA256
- 鍵保護: Windows DPAPI CurrentUser
- 配布: Inno Setup（ユーザー単位インストール）

### モジュール

```text
src/
├── main.rs          エントリーポイント、単一起動
├── app.rs           アプリケーション制御
├── browser.rs       ブラウザ解決・安全な起動
├── profile_scan.rs  Edge/Chrome/Firefox検出
├── model.rs         ドメインモデル
├── storage.rs       SQLite永続化
├── integrity.rs     DPAPI・HMAC・バックアップ
├── url_input.rs     URL検証・表示変換
└── ui/              Win32画面、タイル、設定画面
```

### セキュリティ上の判断

- URLをシェルコマンド文字列へ連結しない。
- ブラウザは `std::process::Command` の引数としてURLとプロファイル識別子を渡す。
- DBに実行ファイルパスを保存しない。
- HMAC鍵は別ファイルへDPAPI暗号化して保存する。
- SQLiteを閉じた状態でDBファイルを署名し、署名は別ファイルに保存する。
- 正常保存前のDBと署名をバックアップし、改変・破損時の復旧候補にする。
- URL履歴設定がOFFの間、URLをファイル・DB・診断ログへ書き出さない。

### 完全性保護の限界

DPAPI CurrentUserとHMACは、設定ファイルの偶発的破損や単純な改変の検出を目的とする。同じWindowsユーザー権限で実行される悪意あるプログラムに対する完全な防御は保証しない。

## 実装順序

1. URLモデル、プロファイルモデル、SQLite、完全性保護
2. ブラウザ検出と起動
3. 単一起動とWin32メイン画面
4. 設定画面
5. インストーラー、利用者文書、性能・実機検証

## 実装報告

### 2026-08-04

- 技術構成をRust + Win32ネイティブUIに確定。
- 配布形式をInno Setupに確定。
- Windowsの既定アプリ変更はユーザー操作とし、アプリは候補登録までを担当する方針に確定。
- 要求一覧、詳細タスク、実装計画を作成。
- Rust / Win32ネイティブの選択画面と設定画面を実装。
- Edge / Chrome / Firefoxプロファイル検出と安全な起動引数生成を実装。
- SQLite保存、DPAPI保護鍵、HMAC-SHA256署名、バックアップ復旧、破損ファイル退避を実装。
- 名前付きMutexとWM_COPYDATAによる単一起動・後続URL転送を実装。
- Inno Setup 6.7.3を導入し、URLハンドラー候補登録を含むセットアップEXEの生成に成功。
- テスト11件、Clippy警告ゼロ、releaseビルドを確認。
- 一時データ環境での初回画面表示は441ms、ワーキングセットは約15.1MB。
- 後続プロセスは31msでURLを既存画面へ転送して終了することを確認。
- WM_CLOSE、閉じるボタン単押し、ESC短押しが終了せず、ESC3秒長押しで終了することを実GUIで確認。
- Windows 11 build 22631でセットアップ／アンインストールを確認。http / httpsの候補登録と削除に成功し、既存の既定アプリ値がインストール前後で変化しないことを確認。
- 空プロファイル環境でも初回スキャン完了フラグを保存し、以後の通常起動で再スキャンしないよう修正。
- URLパターン記録設定（既定OFF）と `UrlHistory` テーブルを実装。ONの場合だけ、末尾・パラメータ値・フラグメントを `*` へ置き換えたパターンを保存する。
- ブラウザ種別ごとの既定アイコンをタイルへ表示。
