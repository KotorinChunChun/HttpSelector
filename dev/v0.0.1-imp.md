# HttpSelector v0.0.1 実装計画・報告

## 実装方針

### 技術構成

- 言語: Rust
- UI: Win32 APIによるネイティブデスクトップUI
- DB: SQLite
- 完全性保護: HMAC-SHA256
- 鍵保護: Windows DPAPI CurrentUser
- 配布: Inno Setup（ユーザー単位インストール）

### モジュール

```text
src/
├── main.rs          エントリーポイント、単一起動
├── app.rs           アプリケーション制御
├── browser.rs       ブラウザ解決・安全な起動
├── profile_scan.rs  Edge/Chrome/Firefox検出
├── model.rs         ドメインモデル
├── storage.rs       SQLite永続化
├── integrity.rs     DPAPI・HMAC・バックアップ
├── url_input.rs     URL検証・表示変換
└── ui/              Win32画面、タイル、設定画面
```

### セキュリティ上の判断

- URLをシェルコマンド文字列へ連結しない。
- ブラウザは `std::process::Command` の引数としてURLとプロファイル識別子を渡す。
- DBに実行ファイルパスを保存しない。
- HMAC鍵は別ファイルへDPAPI暗号化して保存する。
- SQLiteを閉じた状態でDBファイルを署名し、署名は別ファイルに保存する。
- 正常保存前のDBと署名をバックアップし、改変・破損時の復旧候補にする。
- URL履歴設定がOFFの間、URLをファイル・DB・診断ログへ書き出さない。

### 完全性保護の限界

DPAPI CurrentUserとHMACは、設定ファイルの偶発的破損や単純な改変の検出を目的とする。同じWindowsユーザー権限で実行される悪意あるプログラムに対する完全な防御は保証しない。

## 実装順序

1. URLモデル、プロファイルモデル、SQLite、完全性保護
2. ブラウザ検出と起動
3. 単一起動とWin32メイン画面
4. 設定画面
5. インストーラー、利用者文書、性能・実機検証
