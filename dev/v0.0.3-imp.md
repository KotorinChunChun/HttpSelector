# HttpSelector v0.0.3 実装計画・報告

## 実装計画

### フェーズ1: 版と開発資料

- v0.0.2の開発資料を`dev/history`へ移動する。
- アプリ版を0.0.3へ更新し、v0.0.3の要求、設計、実装、タスク資料を作成する。

### フェーズ2: ウィンドウ表示

- Cargoの版から共通タイトルを生成する。
- メイン、設定、既定ルール、アプリ固有ダイアログへ版を表示する。
- 主要画面の最大化を無効化する。

### フェーズ3: ブラウザ前面化

- ブラウザ起動前後のウィンドウを識別し、URLを開いたブラウザを復元・前面化する。
- 既存のプロファイル指定とURL引数を変更しない。
- 単体テスト、フォーマット、Clippy、ビルドを実行する。

## 実装報告

- フェーズ1完了: v0.0.2資料を履歴へ移動し、Cargo版と開発資料をv0.0.3へ切り替えた。Rustテスト50件が成功した。
- フェーズ2完了: Cargo版から画面タイトルを一元生成し、メイン画面の見出し、設定、既定ルール、アプリ固有ダイアログへv0.0.3を表示した。主要3画面は最大化システムコマンドを拒否し、設定画面の最大化ボタンも削除した。Rustテスト52件とdebugビルドが成功した。
- フェーズ3完了: ブラウザ起動前後の可視トップレベルウィンドウを実行ファイルで照合し、新規作成、タイトル変化、Zオーダー変化の順で前面化対象を選ぶ処理を追加した。対象プロセスへ前面化を許可し、最小化時は復元してから前面化する。待機は25ミリ秒間隔、最大2.5秒に制限した。
- ChromeとEdgeのプロファイル引数、Firefoxのプロファイル引数、URL引数は従来どおり個別の引数として渡す。候補選定テスト4件を追加し、全56テスト、fmt、Clippy（警告をエラー化）、debugビルドが成功した。
- 実ブラウザを使う背面、最小化、複数プロファイルの確認は、実ユーザープロファイルへURLを開くため手動確認として残す。
- 既存の未コミット削除`dev/templates/PROJECT_RULE.md`と未追跡`gomi.md`は対象外とする。
- MSIXの生成、署名、インストール、公開は行わない。
