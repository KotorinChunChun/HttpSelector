## 2. 実装方針

- 入れ子は各クエリを一段ずつデコードしてHTTP(S)として検証する。深さ・項目数・長さを制限し、重複した親クエリは曖昧な条件として一致させない。既存urlparts-v1に省略可能な入れ子条件を加え、従来の式を変えない。
- Teamsの特定HTTPSホスト・パスだけをSafe Linksとして認識し、url内のSharePointホストと一意のTeamsCIDを対応付ける。内側条件のない広いルールやお気に入りではアカウントを選ばない。
- 公式ドメイン認識と利用者承認は名称偽装判定だけに作用。承認済みでも全角表記・認証情報・転送先・外部脅威判定を省略しない。承認は端末内Settingsへ保存し、既存の署名・バックアップに含める。
- 設定の折りたたみ・保存と起動の分離を維持。入れ子は追加の折りたたみと共通ボタンで操作し、短縮表示と保存する条件を分離する。

## 3. 影響範囲

## 4. 実装で判明した事項

入れ子条件を知らない旧版0.0.3.3はserdeの未知フィールドを無視して外側ホストだけで一致させる可能性がある。このためDB schemaを5へ上げ、旧版に新形式DBを開かせない。テーブルの構造や従来のルール行は書き換えず、署名済み移行前バックアップの既存経路を使う。
