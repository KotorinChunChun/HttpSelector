# CLI機能試験の実装計画・報告

対応: [要求12](v0.0.3.8-req.md)。2026-10-24。main、PR #1取り込み後の追加実装。版番号変更・配布物生成・外部公開・本PCの導入は含めない。

## 事前確認・方針

139件のRust試験が存在するが、mainのSessionは画面・通信・ブラウザーの関数を直接呼ぶため、保存から起動までの通し試験が不足している。既存の非表示Win32フォーム試験は維持する。コンピュータユースは使わず、業務フローとWin32メッセージ配送をCLIから試験する。

通常の自動試験は一時DB・架空プロファイル・通信/起動の代替境界を使用し、実利用者のDB、Cookie、既定ブラウザー、証明書ストアを変更しない。代替処理だけを試験して本体を素通りさせず、製品と同じSession・Storage・IntegrityManagerを通す。

## 機能別の検証境界

ブラウザーへの元URL・プロファイル・ゲスト引数は自動試験し、画面はWin32 APIと実際のコントロールで試験する。実Edge/Chrome/Firefoxの表示内容、Windowsによる前面化の最終裁定、既定アプリ選択画面のユーザー操作、Store/実MSIX導入、実Quad9の応答は外部依存として区別する。既存の署名付きMSIX検証・インストールCLIを再利用し、通常の一括試験からインストールやOS設定変更を行わない。

「全機能」の対応表は未実施/外部依存を含めて公開し、モック成功を実ブラウザー・実機導入の成功と記載しない。

## 検証結果・追加判断

フェーズ1: `session`をlibへ移し、`SessionHost`の全メソッドを明示実装する方式にした。試験用ホストに製品の既定処理が混入しない。製品mainはNativeHostへ接続し、引数解釈・単一起動・管理イベントループは維持した。既存139件成功、外部Quad91件ignore。fmt・全ターゲットClippy警告拒否成功。

フェーズ2: 通し試験24件、Win32の実メッセージループ/ESC/ネイティブツールチップ取得3件、実WM_COPYDATA送受信1件、ゲストポリシーの拒否・読取異常1件を追加。対話デスクトップ上で最小化からの復帰・前面化を実行する試験は明示オプション用にignoreで追加。全168件成功、ignore2件、fmt・Clippy成功。履歴の検証で列名を誤った試験を検出したため、実スキーマのUrl列へ修正して再試験した。製品DBスキーマは変更していない。

フェーズ3: `test-all.ps1` / `test-all.py` と18機能分野の対応表を追加。一時ログは版設定を読み取って本版logs配下へ出力し、Rustケースと各工程のJSON/JUnit、対応表、標準出力を残す。実在するテスト一覧と実行ケースを照合し、改名・削除・0件の成功扱いを拒否する。Python/Cargoのローカル検出、UTF-8出力、タイムアウトと子プロセスの停止、終了コード伝播に対応。試験入口自身の5件の試験も追加した。

単体試験だけで管理起動を代替しないよう、製品debug EXEの別プロセス統合試験を追加した。初回データ・mutex・窓クラス・パイプを一意に分離し、無表示起動・status・PID不一致拒否・正常停止を通常試験で実行する。表示・ESC・再表示・表示中のstopも明示オプションで実行する。試験IDは既存の絶対データ位置とスキャン停止の両方が指定されたdebug版だけ有効とし、release/MSIXは環境変数を参照しない。

対話デスクトップの初回試験はShowWindowAsyncの対象窓を同じスレッドで作ったため復帰できなかった。ブラウザーと同じく別スレッドでメッセージを処理する試験窓へ修正し、前面化・最小化復帰の実API試験が成功した。また主画面は既存仕様でWM_CLOSEを無視するため、統合試験は製品の終了キーESCを配送して確認した。いずれも試験側の前提を修正し、製品の終了・前面化仕様は変えていない。
