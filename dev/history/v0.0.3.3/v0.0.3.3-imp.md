# HttpSelector v0.0.3.3 実装計画・報告

対応要件: [要求](v0.0.3.3-req.md)。作成日: 2026-10-16。更新日: 2026-10-17。状態: 実装・機能検証・資料更新完了。

## 0. 事前確認

- 現行Cargoは0.0.3+2、表示・管理定義は0.0.3.2。次版を0.0.3.3として資料化する。
- main.rsの手動選択経路からask_domain_associationを毎回呼び、boolしか返さないため質問省略を記憶できない。
- SQLiteのDefaultRulesは一覧順のワイルドカード規則、schema 3。既存Patternを再解釈せず、識別子付きの構造化パターンを追加する。
- 承認済み操作サンプルに従い、条件の保存とURL起動を分離する。未選択のクエリ値・パス値・認証情報を新ルールへ保存しない。
- Rust regexでは先読みを使わず、URL本体の式と選択クエリごとの式をANDで評価する。順序の全組合せを生成しない。表示・コピー・保存・照合で同じ式を使用する。

## 1. 実装順序とコミット単位

1. 条件モデル・正規表現生成・永続化・照合・移行の回帰テスト。
2. 独自Win32フォーム・保存／開く／戻る・既存画面との連携・UI検証。
3. 版整合・現行資料更新・総合検証。

## 2. 要件別方針

- 要求1〜4・9: association_ui.rsを追加。共通Theme/Page/DPIとWindowTitleを使用し、ボタンを幅に応じて折り返す。親画面と同じ最大化無効。長いURLや多数項目は画面全体をスクロール可能にする。
- 要求5・7: association.rsで正規化URLを分解し、固定要素だけを保存する。パスの途中のOFFはその位置の1要素、最後の固定要素より後のOFFは任意階層。全OFFはすべてのHTTP/HTTPS。クエリは生のエンコード済み名前・値の組を固定し、順序に依存しない。重複キーも各組として扱う。
- 要求6: 自動起動は既存順序を保持。質問省略は自動起動に混ぜず、手動選択後だけ照合する。無効・利用不可プロファイルは引き続き手動選択へ戻す。
- 要求7: Pattern内に版付きJSONと生成済み式を格納する。既定ルール一覧では読みやすく表示し、削除・プロファイル変更を可能にする。質問省略はプロファイルに依存しないようDBのProfileIdをNULL可能に移行する。
- 要求8: 保存コールバックでbackup→DB保存→署名を完了してから折りたたむ。失敗時は開いたまま同じ画面へエラー表示。起動処理は「開く」の結果を受けた場合だけ実行する。
- 要求10: Cargo/タイトル/tool.json/MSIX設定を同数値へ更新。MSIXの生成・署名・導入・公開は今回行わない。

## 4. 実装で判明した追加対応

- GUIDなど空白を含まない長い文字列は、標準ボタンの単語折り返しだけでは欠けるため、表示文字列だけを文字幅で折り返す。保存する値は変更しない。
- 正規表現欄はバックスラッシュをコードとして読めるConsolasにした。DPI変更時も作り直し、フォントの所有・破棄を画面に集約した。
- 設定中の後続URLは編集中の対象を置換・強制終了せず保留し、操作後に処理する。直接WM_COPYDATAの2件目は未受理として返し、保留済みURLを失わない。
- 生成済みルールは既存ワイルドカードの入力へ戻して破壊しない。既定ルール一覧では条件要約と読み取り専用式、対象プロファイル変更・削除を提供する。条件変更は削除・再登録とする。
- 表示確認のため版更新をフェーズ2へ前倒しした。既存の0.0.3.2記録は移動せず保持した。

- 回帰検証: 非表示Win32画面を実際にBM_CLICKし、ネイティブ状態と選択モデルが一致することを確認。WM_PRINTCLIENTをDIBへ描画し、OFFの角・枠・背景のピクセルが共通操作ボタンと一致し、ONの背景が共通アクセント色になることを確認。
- 起動中の既存プレビューは上書きせず、検証用ビルドをtarget/button-styleへ分離した。
- 検証結果: ライブラリ・本体103件成功、失敗0、既存の外部照会1件ignore。fmt、Clippy（全ターゲット・警告拒否）、本体debugビルドと分離プレビュービルドが成功。既存プレビューEXEのロックで通常のexamples再リンクは失敗したため、起動中画面を止めず分離先で検証した。
