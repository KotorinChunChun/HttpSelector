# HttpSelector v0.0.3.5 実装計画・報告

対応要求: [v0.0.3.5-req.md](v0.0.3.5-req.md)。2026-10-23、mainでフェーズごとに検証・コミット。状態: 実装・自動検証・署名付きMSIX二拠点公開完了。実機導入/更新は未実施。

## 0. 原因と事前確認

association_uiのSAVEでmaps_teams_accountを必須にし、mainのresolve_profileでも同じ判定に限定していた。この判定は内側のSharePointホストと一意のGUID形式TeamsCIDの完全一致を要求するため、安定したパスだけを選んでも登録できず、UIだけ緩和しても自動起動しない。

CIDの恒久性を仮定しない。URLに同じ安定パスがある範囲の振り分けであり、実Teamsのサインインアカウントを認証して識別する機能ではない。同じ条件に複数アカウントが含まれる場合は区別できない。

- [x] 表示/Cargo/管理定義/MSIX生成設定を0.0.3.5へ揃え、現行資料を更新。全試験・fmt・Clippy・debugビルド・文書リンク検査後にコミット。

## 2. 要求1の実装方針

StoredRuleにmatches_teams_targetを設け、厳密に認識したHTTPS Teams wrapperのurlが展開可能なこと、url内に実際の固定条件があること、全選択条件が一致することを確認する。ホスト・パス・クエリのどれでも可とし、TeamsCIDの書式や存在は独立した必須条件にしない。

SAVEとresolve_profileの両方に同判定を使う。既存の条件JSON・DB schema 5は変更しない。保存済みCID条件は引き続き完全一致させ、利用者の同意なしに広げない。既存の元URL保持・入れ子上限・重複url拒否・競合時の手動選択・お気に入りフォールバック防止・警告を維持する。

## 3. 影響範囲

association、association_ui、main、nested_urlの旧アカウント前提ヘルパー、版設定、利用/開発/FAQとREADME。親Git、実データ、ブラウザー、既存リリースは変更しない。ユーザーの業務URLやトークンをテストやログへ転記せず合成URLだけを使う。
